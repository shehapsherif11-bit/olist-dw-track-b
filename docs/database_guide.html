دليل الداتابيز OlistDW_Project

الخلاصة: عندك 38 table، ومفيش ولا table زيادة. فحصت الداتابيز: كل table فيه code بيستخدمه. عشان كده ممسحتش حاجة.

1) ليه العدد كبير؟

الداتا عبارة عن 8 أنواع (زباين، طلبات، منتجات...). وكل نوع بيعدي على 3 محطات: src و lab و stg. يعني 8 × 3 = 24 table. الباقي 14 بس.

فكر فيها كأنها مطبخ:

الـ schemaالعددفي المطبخوظيفتهاليه متتمسحش
src8المخزننسخة من ملفات الـ CSV زي ما هي. مبنعدلش فيهامطلوبة في الملف (صفحة 2 و 3)
lab8عينات التجربةrecords وهمية بتبدأ بـ LAB_ عشان نختبر التحديثاتمن غيرها اختبارات SCD و X1 تقع
stg8ترابيزة التجهيزالداتا اللي وصلت في كل batch، ونفحصها هنامطلوبة في الملف (صفحة 2 و 5)
dw7الأكل الجاهزالـ Star Schema. دي أهم جزءقلب المشروع
sf2نفس الأكل بتقديم تانيالـ Snowflakeمطلوبة في الملف (صفحة 4)
etl5دفتر المتابعةسجل كل تحميل: نجح ولا فشل، وإيه اللي اترفضمطلوبة في الملف (صفحة 2 و 5)

2) رسمة رحلة الداتا (كل الـ tables)

الأرقام جنب كل اسم هي عدد الـ rows دلوقتي.

3) الـ 8 المتكررين في src و lab و stg

الاسمفيه إيه
Customersالزباين وعنوان التوصيل بتاع كل order
Ordersالطلبات: الحالة والتواريخ
OrderItemsالمنتجات جوه كل طلب والسعر والشحن
Productsالمنتجات والـ category والوزن والمقاس
Sellersالبايعين ومكانهم
CategoryTranslationترجمة اسم الـ category للإنجليزي
Paymentsالدفع
Reviewsتقييمات الزباين

Payments و Reviews الـ Track B مبيعملش منهم fact. بس الملف طالب نحملهم ونفحصهم (صفحة 3 و 7).

4) dw: أهم 7

Tableالـ row الواحد معناهمثال سؤال
FactSalesمنتج واحد اتباع جوه طلب اتسلمبعنا بكام؟
FactProductMonthملخص منتج واحد في شهر واحد (بتاع Track B)المنتج باع كام في ديسمبر؟
DimDateيوم واحدفي أنهي شهر وسنة؟
DimProductمنتج واحدأنهي category؟
DimCustomerشخص واحدمين اشترى؟
DimSellerنسخة واحدة من بياع (لو نقل، يتعمل له row جديد)البياع كان فين وقت البيع؟
DimDeliveryLocationمدينة وولايةالطلب راح فين؟

Fact = أرقام بنجمعها. Dim = وصف الأرقام (مين، إيه، فين، إمتى).

5) etl و sf

Tableفيه إيه
etl.Batchتعريف الـ batches: B1 و B2 و B3 و X1
etl.LoadStateرقم آخر batch نجح
etl.LoadLogrow لكل محاولة تحميل
etl.LoadLogDetailكام row اتضاف أو اتعدل في كل table
etl.DataIssueالـ rows المرفوضة والتحذيرات
sf.DimCategoryكل category مرة واحدة
sf.DimProductالمنتجات، وكل منتج بيشاور على الـ category

فيه كمان Views (استعلامات محفوظة، مش بتخزن داتا): مثلاً mart.vwCategoryMonth و mart.vwProductRanking. هتلاقيهم في SSMS تحت فولدر Views.

6) Star Schema

1 و * معناها: row واحد في الـ Dim ممكن يرتبط بـ rows كتير في الـ Fact. PK = مفتاح الـ table. FK = مفتاح بيشاور على table تاني.

7) Snowflake

8) ترتيب الـ tables جوه SSMS

  1. كليك يمين على فولدر Tables جوه OlistDW_Project.
  2. اختار Filter وبعدين Filter Settings.
  3. في سطر Schema اكتب dw ودوس OK. هتشوف الـ 7 المهمين بس.
  4. عشان ترجع الكل: Filter وبعدين Remove Filter.

9) تعمل Database Diagram جوه SSMS

  1. كليك يمين على فولدر Database Diagrams.
  2. اختار New Database Diagram. لو سألك يعمل support objects دوس Yes.
  3. اختار الـ 7 tables بتوع dw (اضغط Ctrl وانت بتختار)، ودوس Add وبعدين Close.
  4. رتب المربعات: FactSales في النص. الخطوط هتظهر لوحدها.
  5. دوس Ctrl+S وسميه Star Schema.

خلي بالك: لو شغلت run_all.ps1 -Reset الداتابيز بتتمسح وتتبني من جديد، والـ diagram بيتمسح معاها. اعمله بعد آخر تشغيل. وطبيعي إن SSMS يضيف table اسمه sysdiagrams عشان يحفظ الرسمة.
